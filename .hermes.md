# Hermes Project Instructions — Look4Book

Before changing the project, read:

1. `master_plan.md`
2. `70-Project-State/current-state.md`
3. `10-Strategy/PRD.md`
4. Relevant architecture/decision notes

## Working rules

- This is a lean personal project.
- Protect the scanner-to-decision workflow from scope creep.
- Prefer simple, maintainable implementation over infrastructure-heavy solutions.
- Use ISBN/barcode scanning as the MVP identification path.
- Treat cover-image AI recognition as post-MVP.
- Start marketplace pricing with one reliable source before adding more.
- Keep fee, shipping, and recommendation assumptions configurable.
- Never commit API keys, tokens, secrets, or local environment files.
- Update `master_plan.md` checkboxes only when work is actually verified.
- Update `70-Project-State/current-state.md` after meaningful milestones.
- When notes conflict with working code/tests/config, the implementation wins.
